## Этап A — Немедленно (защита от потери/удаления)

- [ ] **A1.** Push всех веток на remote сразу после каждой рабочей сессии.
      Правило: «незапушенного кода не бывает».
- [ ] **A2.** Заменить `LICENSE` (MIT) на проприетарную:
      «© 2026 Pantyuhov DI. All rights reserved…» + краткий запрет копирования/распространения.
- [ ] **A3.** Офсайт-бэкап:
      - скрипт `backend/scripts/backup-offsite.ps1`;
      - назначение — переменная `OFFSITE_DIR` (NAS-шара или папка облачного клиента: Яндекс.Диск и т.п.);
      - копировать последние суточные бэкапы из `backend\backups`, ретеншн ~30 дней;
      - еженедельная полная офлайн-копия;
      - вызов из hourly-бэкапа (`performBackup`) + Task Scheduler на ночь.
- [ ] **A4.** Тест восстановления раз в месяц: поднять сервер из бэкапа в чистой папке.

## Этап B — Гигиена доступа (защита от хищения)

- [ ] **B1.** Найти и удалить протухший `GH_TOKEN` из переменных окружения
      (проверка: `gh auth status` сейчас даёт «token is invalid»).
- [ ] **B2.** NTFS ACL через `icacls`: `backend\.env`, `ssl\server.key`, `ssl\server.crt`,
      `backend\backups` — доступ только учётке администратора + SYSTEM (+ учётке сервиса после B3).
- [ ] **B3.** Запуск сервера под отдельной непривилегированной учёткой Windows
      (без админ-прав), автозапуск сервиса от её имени.
- [ ] **B4.** Проверить приватность обоих GitHub-репозиториев → перевести в Private.
      Для распространения APK — отдельный механизм (private + рассылка, либо public releases-only репо без исходников).

- [ ] **C3.** ⚠️ **Ключевой пункт:** REST API принимает любой `userId` без токенов
