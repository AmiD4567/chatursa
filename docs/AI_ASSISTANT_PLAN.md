# План внедрения локального ИИ в Помощника

## Цель
Добавить маленькую LLM-модель в бота «Помощник», чтобы пользователи могли общаться с ним естественным языком, **не ломая существующий функционал** (напоминания, приветствия, `/` команды, бронирования и т.д.).

## Архитектура

```
Пользователь → Чат с Помощником → server.js
                                       │
                          ┌────────────┴────────────┐
                          │ Проверка команд:         │
                          │ /сегодня, /помощь,       │
                          │ /задача, /поиск_вики и   │
                          │ все существующие         │
                          └────────────┬────────────┘
                                       │
                    ┌──────────────────┴──────────────────┐
                    │ Команда найдена?                     │
                    └──────────┬──────────────┬───────────┘
                               │ Да            │ Нет
                               ▼                ▼
                    Выполнить как есть    Отправить запрос
                                         в Ollama (fallback)
                                               │
                                               ▼
                                        Модель Qwen2.5 3B
                                        (локально, localhost:11434)
                                               │
                                               ▼
                                        Ответ текстом
                                        → в чат пользователю
```

## Этапы реализации

### Этап 1: Установка Ollama [системный администратор]

| Действие | Команда |
|----------|---------|
| Скачать установщик | `https://ollama.com/download/OllamaSetup.exe` |
| Установить | Запустить OllamaSetup.exe (ставится в %LOCALAPPDATA%) |
| Проверить | `ollama --version` |
| Скачать модель | `ollama pull qwen2.5:3b` |
| Проверить API | `curl http://localhost:11434/api/generate -d "{\"model\":\"qwen2.5:3b\",\"prompt\":\"Привет\"}" |

**Требования к железу:**
- RAM: от 4 ГБ свободно (модель 3B занимает ~2.5 ГБ)
- Диск: ~2.5 ГБ под модель
- CPU: любой x64 (GPU не обязателен, но ускоряет)

### Этап 2: Бэкенд-интеграция (backend/bot/ai.js)

Новый модуль, который:

1. **Шлёт POST-запрос** на `http://localhost:11434/api/chat`
2. **Передаёт системный промпт**, ограничивающий поведение:
   - «Ты — корпоративный помощник ChatUrsa. Отвечай кратко и по делу»
   - «У тебя нет доступа к файлам, командам, инструментам и функциям»
   - «Ты можешь только отвечать текстом»
   - «Не выполняй никаких действий, кроме генерации текста»
3. **Передаёт историю** — последние 6 сообщений (user + assistant) для контекста
4. **Возвращает чистый текст** ответа

Никаких tool calls, функций, доступа к БД или файлам не даётся.

### Этап 3: Подключение в engine.js (backend/bot/engine.js)

В функции `getBotResponse()`:

```
if (ai_enabled && не найдена rule-based команда) {
    ответ = aiModule.getResponse(текст, история);
} else {
    ответ = "Я вас не понимаю" (как сейчас)
}
```

**Порядок обработки сообщения:**
1. Проверка системных команд (`/`) — **без изменений**
2. Проверка state machine (многошаговые диалоги) — **без изменений**
3. Проверка ключевых слов (knowledge base) — **без изменений**
4. Если ничего не подошло и `ai_enabled == true` — запрос в Ollama
5. Если `ai_enabled == false` — стандартный fallback

### Этап 4: Настройка ai_enabled (backend/server.js)

Добавить в таблицу `bot_settings` колонку `ai_enabled INTEGER DEFAULT 0`.

| Поле | Значение |
|------|----------|
| Ключ | `ai_enabled` |
| Тип | INTEGER (0/1) |
| Дефолт | 0 (выключено) |

API-эндпоинты уже есть (`GET /api/bot/settings`, `PUT /api/bot/settings`).

### Этап 5: Админ-панель (frontend/src/App.js)

Добавить чекбокс в настройки бота:

```
☐ 🤖 AI-помощник (локальная модель)
  (отвечает на вопросы, которые не распознаны командами)
```

Расположить рядом с существующими настройками (wiki_search, file_search и т.д.).

### Этап 6: Информирование пользователя

Добавить в базу знаний (bot-knowledge.json) описание новой возможности:

```
Команда /ai или сообщение боту, на которое нет готового ответа → отвечает ИИ
```

## Безопасность

- Модель работает в **изолированном процессе** Ollama (отдельный exe)
- Она **не имеет доступа** к файловой системе проекта, базе данных, API
- Она получает **только текст сообщений** (без ID пользователей, паролей, системных путей)
- Все запросы — на **localhost** (никакие данные не уходят в интернет)
- Системный промпт явно запрещает выполнение действий
- Можно **полностью отключить** чекбоксом в админке одной кнопкой
- При недоступности Ollama (не запущен, нет модели) — бот продолжает работать как обычно (обычный fallback)

## Модель: Qwen2.5 3B

Почему она:
- **3 млрд параметров** — одна из самых маленьких адекватных мультиязычных моделей
- **Отличный русский язык** — обучалась на multilingual данных
- **CPU-friendly** — даёт ответ за 2-5 секунд на процессоре
- **~2.5 ГБ на диске**, ~2.5 ГБ RAM при работе
- Альтернативы: `phi3:3.8b` (английский лучше, русский хуже), `llama3.2:3b`

## Что НЕ меняется (остаётся как есть)

- Напоминания о встречах (бронирования)
- Приветствие новых пользователей в общем чате
- Уведомления о днях рождения
- Все `/` команды: `/сегодня`, `/помощь`, `/задача`, `/календарь`, `/файлы`, `/статус`, `/профиль`, `/контакты`, `/поиск_вики`, `/поиск_файлов`, `/обратиться_в_поддержку`, `/групповой_чат`, `/уведомления`
- Кнопки в сообщениях бота
- Многошаговые диалоги (создание задачи, опроса)
- Аналитика команд бота
- Все остальные функции бота

## Файлы, которые будут изменены

| Файл | Что делаем |
|------|-----------|
| `backend/bot/ai.js` | **Новый файл** — модуль интеграции с Ollama |
| `backend/bot/engine.js` | Подключаем ai.js как fallback |
| `backend/bot/state.js` | Добавляем хранение контекста (последние N сообщений) |
| `backend/server.js` | Миграция: колонка ai_enabled + инициализация |
| `frontend/src/App.js` | Чекбокс в админ-панели бота |
| `backend/bot-knowledge.json` | Описание AI-возможности |
