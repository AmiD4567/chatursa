# Аудит проекта ChatApp (Корпоративный мессенджер)

**Дата аудита:** 15.06.2026  
**Аудитор:** Product Manager / UX-исследователь / Системный архитектор  
**Проект:** ChatApp — self-hosted корпоративный мессенджер

---

## 1. КРИТИЧЕСКИЕ НЕДОСТАТКИ (Must-Have Gap Analysis)

| Проблема | Серьезность | Что есть в TG/WA | Что у тебя |
|---|---|---|---|
| **Синхронизация устройств (multi-device)** | 🔴 Критичная | Telegram: до 6 устройств, WhatsApp: до 4 | **Отсутствует**. Весь фронт на React, но нет механизма синхронизации между несколькими инстансами. Если пользователь откроет две вкладки — статусы прочтения и сессии расходятся. UserSocketMap есть, но нет конфликт-резолюции |
| **Push-уведомления на мобильных** | 🔴 Критичная | Работают через FCM/APNs | Есть Web Push (VAPID), но для Android-сборки через Capacitor **не настроен Firebase Cloud Messaging**. Пользователь получит уведомление только если браузер открыт |
| ~~**Офлайн-режим и кэширование**~~ | ~~🔴 Критичная~~ | ~~Сообщения хранятся локально, доступны офлайн~~ | **✅ ИСПРАВЛЕНО**: Service Worker (v2), IndexedDB (messages, chats, outbox), очередь отправки при reconnect, fallback загрузка из кэша при недоступности сервера |
| **Голосовые и видеозвонки** | 🟠 Высокая | Базовый стандарт для корп. мессенджеров | **Отсутствуют**. Для корпоративного продукта — это must-have, а не nice-to-have |
| ~~**Backup/Restore БД**~~ | ~~🟠 Высокая~~ | ~~Облачный бэкап у TG/WA~~ | **✅ ИСПРАВЛЕНО**: Авто-бэкап SQLite по расписанию (каждый час), ротация (24 копии), WAL checkpoint перед копированием, кастомный интервал и директория через .env |
| **LDAP/SSO/Azure AD/Google Workspace интеграция** | 🟠 Высокая | WhatsApp Business API, TG Workspace | **Отсутствует**. Админ создает пользователей вручную. Для B2B-продукта это базовая потребность |
| **Импорт контактов / AD** | 🟡 Средняя | Авто-импорт из телефонной книги | Только ручной поиск. Phonebook работает за счет того, что пользователи сами заполнили данные |

## 2. UX/UI И ПОЛЬЗОВАТЕЛЬСКИЙ ОПЫТ

**Что нарушается или не предоставляется (vs TG/WA):**

1. **Свайп по чату** — нет свайпа влево для архивации/удаления, нет свайпа вправо для отметки прочитанным
2. **Ответ сообщению** — есть, но в TG/WA взаимодействие тактильное с drag/quoted bar. UI-паттерн не дотягивает
3. **Редактирование отправленного** — есть. Но нет истории правок (TG показывает "edited" с датой)
4. **Пересылка без имени** — в TG есть "Hide sender name". forwarded_from содержит sender_name — приватность нарушена
5. **Кастомные уведомления по чатам** — есть в TG: звук, вибрация, LED per-chat. Глобальные настройки
6. **Архив чатов** — отсутствует. TG/WA позволяют архивировать чаты, скрывая их из основного списка
7. **Никнеймы / отображаемые имена** — users имеют `full_name`, но UI не показывает разницу между username и display name. В корп. среде это важно
8. **Emoji-реакции** — есть. Но нет кастомных реакций (TG Premium) или реакции с анимацией (ReactionParticles есть, но выключено по умолчанию)
9. **Поиск** — есть, но нет поиска по файлам, по датам, по отправителю (TG: `from:@user has:photo before:2024`)
10. **Drag & Drop файлов** — есть `isDragOver`, но нет выделенной зоны с UI-фидбеком как в TG

**Вывод:** Базовые паттерны (редактирование, реакции, реплаи, статусы прочтения) — есть. Но UX-гладкости, анимаций, тактильных взаимодействий и фич уровня "удобство для power user" — нет.

## 3. БЕЗОПАСНОСТЬ, ПРИВАТНОСТЬ И ДОВЕРИЕ

**Что есть:**
- ✅ Шифрование на сервере (AES-256-CBC с ключом из .env)
- ✅ JWT-токены
- ✅ Rate limiting
- ✅ Helmet, HSTS, XSS-защита, CSRF
- ✅ bcrypt для паролей
- ✅ 2FA (TOTP) для админов
- ✅ Security logs
- ✅ **Пароль НЕ хранится в localStorage** (исправлено)

**Чего критически не хватает:**

1. ~~**🚨 E2EE — отсутствует**~~
   ~~Серверное шифрование: ключ лежит в `.env`, сервер расшифровывает сообщения перед отправкой~~
   ~~Это НЕ E2EE. Админ сервера может прочитать любое сообщение~~
   ~~Для корпоративного продукта, где "независимость от внешних факторов" — ключевая фишка, отсутствие E2EE — **провал ценностного предложения**~~
   **✅ РЕАЛИЗОВАНО:** ECDH P-256 + AES-256-GCM на клиенте, сервер хранит ciphertext, не имеет доступа к plaintext. Ключи генерируются при входе, хранятся в IndexedDB, публичные ключи обмениваются через REST API. UI переключатель 🔒/🔓 для direct-чатов.

2. **🚨 Нет протокола с Perfect Forward Secrecy**
   - Если ключ скомпрометирован — все прошлые сообщения расшифрованы

3. **🚨 Нет Self-destruct (секретные чаты)**
   - В Telegram секретные чаты с таймером самоуничтожения. У тебя нет

4. **Нет двухфакторной аутентификации для обычных пользователей**
   - TOTP только для админов

5. **Нет аудита доступа к сообщениям**
   - Кто, когда и какое сообщение прочитал — не логируется (security logs логируют только админ-действия)

6. ~~**Пароль хранится в localStorage в кодировке base64**~~
   - ~~`chat_credentials` → password хранится как atob(password)~~
   - ~~Это **нарушение OWASP**. Пароль не должен храниться в localStorage вообще.~~
   - **✅ ИСПРАВЛЕНО**: Пароль удалён из localStorage. Вместо него сохраняется только email (`chat_credentials_email`). Старый ключ принудительно очищается при инициализации.

7. **SQLite не поддерживает concurrent access**
   - Для корпоративного использования с 50+ одновременными пользователями начнутся `SQL_BUSY` ошибки

**Исправлено из предыдущих сессий:**
- ~~Без FCM — Android не получает уведомления в фоне~~ **✅ ВЫПОЛНЕНО** (Firebase Admin SDK v14 + ChatFirebaseMessagingService + fcm_tokens API)
- ~~Web Push не работал — клиент не подписывался~~ **✅ ВЫПОЛНЕНО** (подписка в index.js, регистрация при логине, отписка при логауте)

## 4. КОНКУРЕНТНЫЕ ПРЕИМУЩЕСТВА И УНИКАЛЬНОСТЬ (The "Why You?" Factor)

**Текущее УТП:** "Корпоративный мессенджер, который разворачивается внутри компании и не зависит от внешних факторов или блокировок"

**Проблема:** Это не УТП, это **базовое требование** для Enterprise. Slack, Mattermost, Rocket.Chat, Element (Matrix) — все self-hosted.

**Почему пользователь должен выбрать тебя, а не Mattermost / Rocket.Chat?** У них 10+ лет разработки, плагины, интеграции, LDAP, compliance.

**3 идеи для УТП:**

1. **"Zero-trust корпоративный мессенджер с E2EE и полным офлайн-режимом"** — сделай E2EE обязательной (Signal-протокол), а не опциональной. E2EE в self-hosted решении — редкое и сильное УТП. Ни Mattermost, ни Rocket.Chat не имеют E2EE по умолчанию.

2. **"Мессенджер, который работает без интернета — полный LAN-режим"** — если приложение может полноценно работать в изолированной сети (военные, госсектор, заводы), это сильная ниша. Особенно с синхронизацией через mesh-сеть.

3. **"Мессенджер + корпоративный портал"** — уже есть календарь, задачи, бронирование переговорной, телефонная книга, дни рождения. Преврати это в полноценный **Digital Workplace**: HR-портал, корпоративные объявления, опросы, документооборот. Slack/TG не закрывают глубокую enterprise-вертикаль.

**Вывод:** Сейчас проект конкурирует с TG/WhatsApp по базовому функционалу, но проигрывает. Ниша self-hosted enterprise — перегрета (Mattermost, Rocket.Chat, Element). Нужен **узкий фокус**: E2EE-first или offline-first или workplace-all-in-one.

## 5. ПРИОРИТИЗИРОВАННЫЙ ROADMAP

### Phase 1 (MVP) — Без этого запускаться нельзя (0-3 месяца)

| # | Фича | Обоснование |
|---|---|---|
| ~~1~~ | ~~**E2EE (ECDH + AES-256-GCM)**~~ | ~~Критическая дыра в безопасности. Без E2EE УТП "независимость" — пустой звук~~ **✅ ВЫПОЛНЕНО** (backend + frontend, ECDH P-256 + AES-GCM, управление ключами через IndexedDB, UI переключатель 🔒/🔓) |
| ~~2~~ | ~~**Multi-device синхронизация**~~ | ~~Без нее пользователь не может работать с ПК + телефон одновременно~~ **✅ ВЫПОЛНЕНО** (getUserSockets/emitToUser helpers, mark_read/forward/join для всех сессий, deviceId, user_device_sessions, UI управления сессиями в настройках) |
| ~~3~~ | ~~**Service Worker + IndexedDB (офлайн-режим)**~~ | ~~Offline должен быть: кэш последних сообщений, отправка при восстановлении соединения~~ **✅ ВЫПОЛНЕНО** |
| ~~4~~ | ~~**Нативные PUSH (FCM для Android)**~~ | ~~Web Push не работает на мобильных в фоне~~ **✅ ВЫПОЛНЕНО** (Firebase Admin SDK на бэкенде, fcm_tokens БД, ChatFirebaseMessagingService на Android, интеграция с sendPushNotification + гугл-сервисы подключены) |
| 4.1 | **APNs для iOS** | Настроить Apple Push Notification service |
| ~~5~~ | ~~**Резервное копирование БД (auto-backup)**~~ | ~~Краш сервера не должен убивать данные. SQLite WAL ненадежен~~ **✅ ВЫПОЛНЕНО** |
| 6 | **Миграция SQLite → PostgreSQL (или SQLite с WAL2/репликацией)** | SQLite не выдержит 50+ concurrent users |

### Phase 2 (Retention) — Заставит вернуться на второй день (3-6 месяцев)

| # | Фича | Обоснование |
|---|---|---|
| 7 | **Голосовые и видеозвонки (WebRTC + TURN)** | Без звонков корп. мессенджер — половина продукта. P2P звонки без внешних серверов |
| 8 | **LDAP / SSO / OIDC интеграция** | Enterprise не будет вручную заводить пользователей. Интеграция с AD/Google/Azure |
| 9 | **Архив чатов + поиск с фильтрацией (по дате, файлам, отправителю)** | Power users не могут жить без продвинутого поиска |
| 10 | **Threads с уведомлениями** | В TG — треды, в Slack — threads. Без них групповые чаты превращаются в хаос |

### Phase 3 (Killer-features) — Твоя ниша (6-12 месяцев)

| # | Фича | Обоснование |
|---|---|---|
| 11 | **Self-destruct сообщения / секретные чаты** | Если есть E2EE — добавь "прочитал и забыл". Сильное УТП для enterprise |
| 12 | **Полный LAN-режим (P2P mesh синхронизация)** | При разрыве интернета чаты продолжают работать через локальную сеть. Для заводов/нефтянки/шахт — это killer |
| 13 | **Корпоративный портал (HR, опросы, документы, согласования)** | Преврати проект из "еще один чат" в "экосистема компании". Интеграция с 1С/Bitrix24/etc. |
| 14 | **Аудиторский лог (compliance-ready)** | Для банков и госсектора: лог всех действий, неизменяемость, экспорт для регуляторов |
| 15 | **Боты с API (Slack-подобные /commands)** | Есть бот-помощник, но нет публичного Bot API для интеграций |

---

**Итоговая оценка:** Проект — добротный MVP уровня "дипломная работа / стартап на ранней стадии". Кодовая база чистая, архитектура понятна, функционал покрывает 80% базовых мессенджер-фич. **Для enterprise-продукта всё ещё не хватает:** звонки, SSO, PostgreSQL. **Выполнено из roadапа:** ✅ фикс пароля в localStorage → ✅ auto-backup → ✅ офлайн-режим → ✅ E2EE → ✅ multi-device → ✅ Push/FCM (Android). Следующие шаги: 🟡 APNs для iOS, SQLite → PostgreSQL.
