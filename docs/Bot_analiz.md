Анализ бота-помощника «Помощник»

    Общая архитектура

    Бот — rule-based (правильно-ориентированный), без внешних API. Вся логика в одном файле server.js (4915 строк).
     Работает по схеме:

     1 ввод пользователя → проверка команды (/команда) → поиск ключевых слов → ответ из словаря

    ---

    🔴 Критические проблемы

    1. SQL-инъекции в запросах бота

     1 // server.js ~строка 3970 — прямая подстановка переменных!
     2 const tasksToday = db.exec(`
     3   SELECT id, title, task_time FROM calendar_tasks
     4   WHERE user_id = '${onlineUser.id}' AND task_date LIKE '${todayIso}%'
     5 `);
    Это работает, но крайне небезопасно. Если onlineUser.id будет содержать SQL-код — выполнится. Нужно
    использовать prepared statements:

     1 const stmt = db.prepare(`SELECT id, title, task_time FROM calendar_tasks WHERE user_id = ? AND task_date
       LIKE ?`);
     2 stmt.bind([onlineUser.id, todayIso + '%']);

    2. Дублирование keywordMap
    Объект keywordMap определён дважды:
     - Один раз внутри функции getBotResponse() (~строка 3318)
     - Второй раз как свойство botKnowledge.searchIndex (~строка 3479)

    Они не синхронизированы — в одном есть слова, которых нет в другом. Это приводит к тому, что одни и те же фразы
     обрабатываются по-разному в зависимости от пути.

    3. Жёстко закодированная база знаний
    Весь контент бота — JS-объект botKnowledge внутри server.js. Чтобы изменить ответ бота, нужно:
     1. Открыть server.js
     2. Найти нужный ключ
     3. Изменить текст
     4. Перезапустить сервер

    Решение: вынести базу знаний в отдельный JSON-файл (bot-knowledge.json) и загружать её при старте. Это позволит
     менять ответы без перезапуска (с кэшированием).

    🟡 Средние проблемы

    4. Нет rate-limiting для бота
    Пользователь может спамить командами /помощь — сервер будет отвечать на каждую. Нужно добавить простую защиту:

     1 const botCooldowns = new Map(); // userId -> timestamp
     2
     3 function isBotRateLimited(userId) {
     4   const now = Date.now();
     5   const last = botCooldowns.get(userId);
     6   if (last && now - last < 2000) return true; // 2 сек между командами
     7   botCooldowns.set(userId, now);
     8   return false;
     9 }

    5. Неэффективные запросы к БД в /сегодня
    Каждый вызов /сегодня делает 3 полных скана:

     1 // Каждое обращение — полный SELECT без индексов
     2 db.exec(`SELECT username, avatar FROM users WHERE birth_date IS NOT NULL`);
     3 db.exec(`SELECT title, start_time, end_time FROM meeting_room_bookings ...`);

    Решение: кэшировать результаты на 1 минуту или добавить индексы в БД.

    6. Приветственное сообщение слишком длинное (~40 строк текста)
    Оно отправляется при каждом первом входе нового пользователя. Лучше разбить на серию коротких сообщений с
    кнопками (step-by-step), как уже реализовано в /онбординг.

    7. Поиск по ключевым словам — грубый includes()

     1 if (text.includes(keyword)) { // keyword = 'чат'
    Фраза "Я не хочу чат с ботом" → сработает на "/чат". Нужно использовать более умный поиск:
     - Разбиение на слова
     - Проверка на частичное совпадение только для корней слов
     - Приоритет точных команд (/команда) над ключевыми словами

    🟢 Возможные улучшения

    8. Вынести бота в отдельный модуль
    Сейчас server.js — монолит. Бот можно вынести в bot.js:

     1 backend/
     2 ├── server.js          # Express + Socket.IO (основной поток)
     3 ├── bot/
     4 │   ├── index.js       # Экспорт бота
     5 │   ├── knowledge.json # База знаний (JSON)
     6 │   ├── engine.js      # getBotResponse()
     7 │   └── commands.js    # Специальные команды (/сегодня, /контакты)

    9. Добавить контекст разговора
    Сейчас каждое сообщение бота — независимый запрос. Нет памяти о предыдущих сообщениях в рамках диалога. Можно
    добавить простой state machine:

     1 const botConversations = new Map(); // socketId -> { step, context }

    10. Добавить аналитику использования бота
    Сейчас есть /api/bot/stats/:userId — но это статистика пользователя, а не использования бота. Нужно
    отслеживать:
     - Сколько раз вызвана каждая команда
     - На какие кнопки чаще всего нажимают
     - Какие фразы не распознаются (fallback)

    11. Поддержка Markdown в ответах
    Бот использует *текст* для жирного шрифта, но это парсится только на фронтенде через formatBotText(). Если
    форматирование сломается — бот будет показывать сырые звёздочки.

    12. Фронтенд: раздельный рендеринг сообщений бота
    В App.js (~строка 5908) сообщения бота обрабатываются отдельно от обычных:

     1 {isBotMessage(message) ? formatBotText(message.text) : wrapEmojisInText(message.text)}
    Это дублирование логики форматирования. Лучше один компонент MessageContent с параметром isBot.
